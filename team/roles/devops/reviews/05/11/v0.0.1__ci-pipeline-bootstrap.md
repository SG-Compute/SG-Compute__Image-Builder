# DevOps review — CI pipeline bootstrap

**Version:** v0.0.1
**Date:** 2026-05-11
**Pack reference:** §10 (`dev-ops-brief.md`)

## What landed

Three workflows under `.github/workflows/`:

| Workflow   | Trigger                              | Gates |
|------------|--------------------------------------|-------|
| `pr.yml`   | Pull requests to `main` or `dev`     | lint + unit (Py 3.11 / 3.12) + integration |
| `main.yml` | Push to `main` or `dev`              | everything in `pr.yml` + zipapp build + auto-tag (main only) |
| `tag.yml`  | Push of tags matching `v*`           | E2E suite (gated by `SGI_E2E_ENABLED=1`) + release artefact |

Plus a `Makefile` mirroring the CI commands so `make test` locally matches CI.

## Coverage gate

`pyproject.toml`'s `[tool.coverage.run]` is wired; `pr.yml` runs
`pytest --cov-fail-under=90` on the unit suite. The 90% threshold per pack
§10 is honoured.

## Open follow-ups

- **Secrets:** `AWS_E2E_ACCESS_KEY_ID`, `AWS_E2E_SECRET_ACCESS_KEY`, `CODECOV_TOKEN` to be configured in GitHub repo settings before the first tag.
- **Branch protection:** rules need to be applied in the GitHub UI; required checks are `lint-and-typecheck`, `unit-tests (3.11)`, `integration-tests`, `build-zipapp`.
- **Integration SSH service:** `pr.yml` declares an `openssh-server` service for the SSH provider tests; the integration step is currently a placeholder that just runs `pytest` against an empty integration suite. The actual SSH-host fixture wires up in M1.
- **AWS IAM policy:** narrowly-scoped policy for the E2E user (per pack §10) needs to be drafted and applied. The list of actions is in §10 "Required secrets" - to be turned into a runbook in `team/roles/devops/runbooks/`.
- **Cost ceiling:** $10/day E2E budget per pack §10. No spend until E2E is enabled.

## What's intentionally NOT here

- Nightly schedule workflow (deferred until E2E is real)
- Dependabot config (pack §10 marks this as v0.2)
- Dependency security scanning (pack §10 marks this as v0.2)
