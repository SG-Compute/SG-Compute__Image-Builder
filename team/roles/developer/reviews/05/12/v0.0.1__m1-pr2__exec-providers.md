## Calibration refinements found during PR2

Two more places where raw `Safe_Str` (the pack's default) silently corrupted real-world values:

| Field | Pack says | We used | Why |
|-------|-----------|---------|-----|
| `Exec_Provider__Sg_Compute.instance_name` | `Safe_Str` | `Safe_Str__Id` (L1) | `Safe_Str` strips `-` -> `my-vllm-1` becomes `my_vllm_1`. `Safe_Str__Id` allows `-` and `_`. |
| `Exec_Provider__Sg_Compute.region` | `Safe_Str` | `Safe_Str__Slug` (L1) | Same hyphen problem on `eu-west-2`. Slug also enforces lowercase, which AWS regions are anyway. |

Both are L1 picks - existing OSBot primitives that fit. The lesson from
the 12-May calibration addendum holds: inspect `regex` / `regex_mode` /
`trim_whitespace` before trusting an L1 default. Both these primitives
are still REPLACE-mode (silent transformation), but the regex actually
matches the domain so it's safe here. If someone passes
`instance_name='my+vllm'`, it'd silently become `my_vllm` - that's a
runtime concern that `sg lc` itself will catch when it can't find the
instance.

No new L3 types in PR2.

## Type_Safe behaviour notes

1. **`@type_safe` on the abstract base.** Every method on `Exec_Provider`
   carries `@type_safe`. This validates inputs even on the base before
   the `NotImplementedError` raises - protects subclass authors who copy
   the signature.

2. **Subclasses keep `@type_safe` on each override.** Per the decorator
   guide v3.63.3, decoration doesn't inherit; each override declares its
   own contract.

3. **No `abc.ABC` mixed in.** Type_Safe + ABC's metaclass can fight.
   The pack's pattern is plain `class X(Type_Safe): raise NotImplementedError()`
   and we follow it.

4. **`# type: ignore[assignment]` on Process_Text `= None` defaults.**
   Same pattern as PR1: mypy can't see Type_Safe's runtime conversion of
   `None` to a sentinel value, so we narrow-suppress per line.

## Follow-ups

1. **Sg_Compute.exec_command edge case:** today the wrapper's exit_code on
   the text-fallback path is the *wrapper's* exit_code, not the wrapped
   command's. If `sg lc` exits 0 but the inner command exits 1, we'd
   report 0. The `--json` path doesn't have this problem. Document
   this in the Sg_Compute follow-up briefs once `--json` exists.

2. **Spike-results brief absence** is now tracked in
   `humans/dinis_cruz/feedback-to-sg-compute.md`. When the spike does run,
   we should retro-validate the calibrated types and exec flow against
   what the spike actually used.

3. **PR3 candidate: `Exec_Provider__SSH`** plus the three AWS helpers from
   the pack. Needs osbot-utils SSH + ephemeral EC2 lifecycle code.

4. **PR4 candidate: Storage provider family** - `Storage` abstract base,
   `Storage__In_Memory`, `Storage__Local_Disk`, `Storage__S3`, `Storage__Factory`.
   `In_Memory` is the test double, `S3` is the production target.
